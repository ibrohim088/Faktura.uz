TEST-CASE: ТТН — сохранение и повторное использование адресов (Мои адреса / Адреса партнера)
==========================================================================================

Предусловие для всех кейсов: пользователь авторизован, открыта форма создания ТТН, раздел адресов груза.
Используемые методы API ГНК:
  GET  /provider/api/{lang}/waybills-v2/utils/companies/{tinOrPinfl}
  POST /provider/api/{lang}/waybills-v2/utils/companies/add-address
  POST /provider/api/{lang}/waybills-v2/utils/companies/update-address
  POST /provider/api/{lang}/waybills-v2/utils/companies/delete-address


------------------------------------------------------------------------------------------
1. ИНТЕРФЕЙС ТТН (кнопки)
------------------------------------------------------------------------------------------

TC-01. Отображение кнопок «Мои адреса» и «Адреса партнера»
  Шаги:       1. Открыть форму создания ТТН.
  Ожидаемо:   В разделе адресов груза отображаются обе кнопки: «Мои адреса» и «Адреса партнера».
  Результат:  Есть два кнопки "Мои адрес" и "Адреса партнера" 

TC-02. Кнопка «Адреса партнера» disabled без данных грузополучателя
  Шаги:       1. Открыть форму ТТН, не вводя данные грузополучателя.
              2. Попытаться нажать «Адреса партнера».
  Ожидаемо:   Кнопка неактивна (disabled), drawer не открывается.
  Результат:  Если поля "Грузополучатель" не указона ничего при этапе создание то кнопка Адреса партнера становится disable, и drawer не открывается.

TC-03. Кнопка «Адреса партнера» становится активной после ввода грузополучателя
  Шаги:       1. Ввести/выбрать грузополучателя (ИНН/ПИНФЛ).
  Ожидаемо:   Кнопка «Адреса партнера» становится активной.
  Результат:  Для того чтобы сделать его Enable в поля "Грузополучатель" надо передать значение тогда поля "«Адреса партнера" она станет доступным. передал ИНН а после ПИНфЛ он также показал значение

TC-04. Кнопка «Адреса партнера» снова disabled при очистке грузополучателя
  Шаги:       1. Выбрать грузополучателя.
              2. Очистить поле грузополучателя.
  Ожидаемо:   Кнопка «Адреса партнера» снова disabled.
  Результат:  после удаление ИНН либо ПИНФЛ с поля "Грузополучатель" то кнопка "Адреса партнера" становятся снова disable

TC-05. Кнопка «Мои адреса» всегда активна
  Шаги:       1. Открыть форму ТТН без заполнения других данных.
  Ожидаемо:   Кнопка «Мои адреса» активна и открывает drawer.
  Результат:  Мой адрес он всегда активен и открывает drawer и внутри есть адреса если они были добавлены.

2. «МОИ АДРЕСА» (drawer)
------------------------------------------------------------------------------------------

TC-06. Открытие бокового меню «Мои адреса»
  Шаги:       1. Нажать «Мои адреса».
  Ожидаемо:   Открывается боковое меню (Drawer) со списком сохраненных адресов текущей организации.
              В запросе GET .../companies/{tinOrPinfl} передан ИНН/ПИНФЛ текущей организации.
  Результат:  после нажатие на кнопку "Мои адреса то открывается drawer список внутри него есть мои место"

TC-07. Поля, отображаемые для каждого адреса
  Шаги:       1. Открыть «Мои адреса» (в организации есть сохраненные адреса).
  Ожидаемо:   Для каждого адреса отображаются: название/краткое описание (при наличии), область,
              район, махалля, улица, полный адрес.
  Результат:  есть поля а также они отоброжаются нормально

TC-08. Пустой список адресов
  Предусл.:   У организации нет сохраненных адресов.
  Шаги:       1. Нажать «Мои адреса».
  Ожидаемо:   Drawer открывается, показано пустое состояние (сообщение), кнопка «Добавить новый адрес» доступна.
  Результат:  после нажатие кнопки "Мои адреса" откроется Drawer и внутри будет написона "Мои адреса" после есть кнопка для выхода с Drawer после внизу есть часть филтра внутри него есть поиск кнопка филтара которые делает реверс в списе адресов, после есть список самого адресов внутри каждого изних есть поля (Область:, Район:, Махалля:, Улица:, Дом:, Полный адрес:) потом наверху в правом углу есть два кнопки первые это для того чтобы радактировать второй для удаление адреса

TC-10. Закрытие drawer
  Шаги:       1. Открыть «Мои адреса».
              2. Закрыть drawer (крестик / клик вне области / Esc).
  Ожидаемо:   Drawer закрывается, данные формы ТТН не потеряны.
  Результат:  есть кнопка

3. ДОБАВЛЕНИЕ АДРЕСА (модальная форма)
------------------------------------------------------------------------------------------

TC-11. Открытие формы добавления адреса
  Шаги:       1. Открыть «Мои адреса».
              2. Нажать «Добавить новый адрес».
  Ожидаемо:   Открывается модальное окно с полями: Область (DropDown), Район (DropDown),
              Махалля (DropDown), Адрес (текст), Улица (текст); есть кнопки «Показать на карте» и «Сохранить».
  Результат:  После нажатие на кнопку Добавить новый адрес то появится модальное окно внутри него будет поля (Область: DropDownList, Район: DropDownList, Махалля: DropDownList, Улица: Input, Дом: Input, Полный адрес: Input)

TC-12. Каскадная зависимость выпадающих списков
  Шаги:       1. Выбрать Область.
              2. Проверить список Районов.
              3. Выбрать Район.
              4. Проверить список Махалей.
  Ожидаемо:   Районы соответствуют выбранной области, махалли — выбранному району.
              До выбора области район недоступен, до выбора района махалля недоступна.
  Результат:  Для того чтобы поля Район и Махаля не были недоступными сначала должна выбратса поля Область после для того чтобы махаля было выбрата надо чтобы было выбрана поля Район после этого поля махале будет имена те районые которые были внутри этого Области и Района

TC-13. Смена области сбрасывает район и махаллю
  Шаги:       1. Заполнить Область, Район, Махаллю.
              2. Сменить Область.
  Ожидаемо:   Поля Район и Махалля сбрасываются.
  Результат:  Посли смены Области поля Район и махаля сбрасываются полси сменя Района поля махаля сбрасывается тоже

TC-14. Успешное сохранение адреса (позитивный)
  Шаги:       1. Заполнить все обязательные поля корректными данными.
              2. Нажать «Сохранить».
  Ожидаемо:   Вызван add-address (успех), модальное окно закрывается, адрес появляется в списке
              «Мои адреса» без перезагрузки страницы.
  Результат:  сохранил потом применил новые сохранйные адрес странитса не перезогрузилаь не разу

TC-15. Валидация: пустые обязательные поля
  Шаги:       1. Оставить обязательные поля пустыми.
              2. Нажать «Сохранить».
  Ожидаемо:   Адрес не сохраняется, под незаполненными полями показаны сообщения об ошибке,
              запрос add-address не отправляется.
  Результат:  Обизательные поля они обизательные если их не зополнить то выйдет ошибка "Заполните обязательные поля: область, район, улица"

TC-16. Валидация: заполнено частично (по одному пропуску)
  Шаги:       1. Поочередно оставлять пустым по одному полю (Область / Район / Махалля / Адрес / Улица).
              2. Нажать «Сохранить».
  Ожидаемо:   Для каждого случая сохранение блокируется, подсвечено именно незаполненное поле.
  Результат:  Заполнил частично заполнил только те поля которые были указоны как обизательные тоисть эти поля (Область, Район, Улица) не зополнил поля (махалля и дом) поля (Полный адрес) он сам в автомате забрал поля с остальных зополненх полей

TC-17. Поля «Адрес» и «Улица»: спецсимволы, кириллица, латиница, цифры
  Шаги:       1. Ввести в поля значения вида: "ул. Навои, 12/А", "Amir Temur 5", "O'zbekiston".
              2. Сохранить.
  Ожидаемо:   Допустимые символы сохраняются и отображаются без искажений.
  Результат:  в поля Улитца и Дом можна написать все что угодна а поля (Область, Район и Махалля) так как они DropDawnList уних только можна выбрать подходяшие невозможна чтота написать самому 

TC-18. Поля «Адрес» и «Улица»: очень длинная строка
  Шаги:       1. Ввести значение с превышением допустимой длины.
              2. Сохранить.
  Ожидаемо:   Ввод ограничен или показана ошибка валидации; приложение не падает.
  Результат:  Нет огроничение длины

TC-19. Поля «Адрес» и «Улица»: пробелы / XSS-строка
  Шаги:       1. Ввести только пробелы; затем строку <script>alert(1)</script>.
              2. Сохранить.
  Ожидаемо:   Пробелы не считаются заполненным значением; скрипт не выполняется, строка экранируется.
  Результат:  Нет не выполнилось считала как обычные строку

TC-20. Дубликат адреса
  Шаги:       1. Сохранить адрес.
              2. Добавить еще раз адрес с теми же данными.
  Ожидаемо:   Поведение соответствует требованиям (запрет дубликата с сообщением либо создание второй записи) —
              зафиксировать фактический результат.
  Результат:  можна дублировать

TC-21. Отмена добавления
  Шаги:       1. Заполнить часть полей.
              2. Закрыть модальное окно без сохранения.
  Ожидаемо:   Адрес не создан, запрос add-address не отправлялся; при повторном открытии форма пустая.
  Результат:  Для того чтобы закрыть надо нажыть на две кнопки первые это "X" второй это "Отмена" если изменить адрес и после нажать на нопку "X" или "Отмена" то модальнео окно закроется и все останетса как было раньше для того чтобы сохранить надо прям нажать на кнопку сохранить для того чтобы выйти надо сделат либо сохранить либо сделать отмена или нажать на "X"

5. АВТОЗАПОЛНЕНИЕ В ТТН
------------------------------------------------------------------------------------------

TC-22. Выбор своего адреса заполняет поля погрузки
  Шаги:       1. Открыть «Мои адреса».
              2. Выбрать сохраненный адрес.
  Ожидаемо:   Drawer закрывается, поля адреса погрузки автоматически заполнены всеми сохраненными
              реквизитами (область, район, махалля, адрес, улица).
  Результат:  Нажымаем на кнопку "Мои адреса" после открывается Drawer и там выбераем один сохраненые адрес после нажатие на сохраненеые адрес поля которые находятса внутри "Адрес погрузки они зополняются"

TC-23. Ручное редактирование после автозаполнения
  Шаги:       1. Выбрать сохраненный адрес.
              2. Изменить значения в полях погрузки вручную.
  Ожидаемо:   Поля редактируются; сохраненный адрес в справочнике не меняется.
  Результат:  в поле "Адрес погрузки" можна вручную редактировать но полное поля нельза можна только (Область, Район, Улица, Дом)

TC-24. Повторный выбор другого адреса перезаписывает поля
  Шаги:       1. Выбрать адрес A.
              2. Снова открыть «Мои адреса» и выбрать адрес B.
  Ожидаемо:   Поля погрузки содержат данные адреса B (без остатков адреса A).
  Результат:  Да можна выбрать повторно

6. «АДРЕСА ПАРТНЕРА»
------------------------------------------------------------------------------------------

TC-25. Открытие списка адресов партнера
  Предусл.:   Введен грузополучатель.
  Шаги:       1. Нажать «Адреса партнера».
  Ожидаемо:   Открывается отдельное боковое меню; запрос GET .../companies/{tinOrPinfl} отправляется
              с ИНН/ПИНФЛ партнера (не своей организации); отображается список адресов партнера.
  Результат:  Посли нажатие на кнопку запрос отправляется на "https://test.faktura.uz/ru/roaming/getwaybillcompanyaddresses?tinorpinfl=302378936" этот url адрес после он открывает Drawer лист внутри него есть филтр по название и филтр по reverse sort, после лист адресов

TC-26. Выбор адреса партнера заполняет поля разгрузки
  Шаги:       1. Открыть «Адреса партнера».
              2. Выбрать адрес.
  Ожидаемо:   Поля разгрузки автоматически заполнены; поля погрузки не затронуты.
  Результат:  После выбора адреса со списка Адрес партнера не трогает поля погрузки

TC-27. У партнера нет адресов
  Предусл.:   У выбранного партнера нет сохраненных адресов.
  Шаги:       1. Нажать «Адреса партнера».
  Ожидаемо:   Показано пустое состояние, ошибок нет.
  Результат:  Если Адреса партнера будет пустым то в UI покажет что "Нет сохранённых адресов" но и внутри response поля error стоит null в поле address пустой массив(array)

TC-28. Смена партнера обновляет список адресов
  Шаги:       1. Выбрать партнера A, открыть «Адреса партнера».
              2. Закрыть, сменить партнера на B, открыть снова.
  Ожидаемо:   Показаны адреса партнера B, а не A.
  Результат:  если сменить поля A на B Грузополучатель то внутри Адрес доставки будет уже партнер B

TC-29. Адреса партнера доступны только для выбора
  Шаги:       1. Открыть «Адреса партнера».
  Ожидаемо:   Редактирование/удаление чужих адресов недоступно (проверить по требованиям), доступен выбор.
  Результат:  адрес парнера можна только выбрать нельза делать редактировать или же удаление

8. API / ОБЩИЕ ПРОВЕРКИ
------------------------------------------------------------------------------------------

TC-30. API: получение списка адресов организации
  Шаги:       1. Отправить GET .../utils/companies/{tinOrPinfl} с валидным ИНН/ПИНФЛ.
  Ожидаемо:   200 OK, в ответе список адресов с полями (область, район, махалля, адрес, улица).
  Результат:  https://test.faktura.uz/ru/roaming/getwaybillcompanyaddresses?tinorpinfl=305395454 для того чтобы получить Мои адреса


TC-32. API: add-address, update-address, delete-address
  Шаги:       1. Выполнить каждый метод с валидными и невалидными данными.
  Ожидаемо:   Валидные данные — успех; невалидные — ошибка валидации с понятным ответом.
  Результат:  сделал с валидным данными все прошло хорошо, если сделать чтота не валидное в протсесе создание то выйдет ошибка в Ui как msg там будет валидное обеснение об ошибки 

TC-33. Изоляция данных организаций
  Шаги:       1. Войти под организацией A, добавить адрес.
              2. Войти под организацией B, открыть «Мои адреса».
  Ожидаемо:   Адрес организации A не виден организации B.
  Результат:  можна сделать так есть два организации если зайти через первые (A) потом в поля Получатель передать (B) потом войти в организатцыю (B) после добавить новое адрес потом вернутса на A после передать на поля Получатель B после выбрать можна новые адрес которые добавил сам B а не ктота другой 

TC-36. Обновление страницы
  Шаги:       1. Добавить адрес, обновить страницу (F5), открыть «Мои адреса».
  Ожидаемо:   Адрес сохранен и отображается в списке.
  Результат: Если намерено обнавить браузер тоисть сделать F5 то все сам документ он очистетса но список адресов он останет так как мы его добавили и сохранили.
