Поле телефона принимает только перечисленные ниже форматы. При создании документа, если передать другой формат, документ не создастся.
В UI необходимо сделать понятное отображение ошибки: при неправильном вводе номера показывать допустимые форматы. Пример:

"Phones": [
    "(+998 77) 088-65-05",
    "+998 (77) 088-65-05",
    "+998770886505",
    "+998 77 088-65-05"
]

Правильные форматы номеров телефона организации:
  (+998 77) 088-65-05,
  +998 (77) 088-65-05,
  +998770886505,
  +998 77 088-65-05

Всё, чего нет в этом списке, считается неправильным форматом номера (при вводе номера телефона пользователь видит допустимые форматы и получает предупреждение при несоответствии требованиям роуминга).

BranchCode и BranchName заполняются только тогда, когда при создании документа в UI была выбрана организация с филиалом: название и код филиала попадают в BranchName и BranchCode.

ЗАДАЧА: Актуализация подписываемого JSON документа «Письмо НК» (роуминг)
================================================================================

ОПИСАНИЕ
--------------------------------------------------------------------------------
В роуминге изменились требования к подписываемому JSON документа типа
«Письмо НК». Необходимо:
  - актуализировать структуру JSON в соответствии с новыми требованиями;
  - доработать заполнение данных подписанта;
  - добавить возможность выбора филиалов организаций отправителя и получателя;
  - реализовать проверку формата номера телефона при вводе с отображением
    допустимых форматов, предусмотренных документацией роуминга.


ТРЕБОВАНИЯ
--------------------------------------------------------------------------------

1. Изменить структуру подписываемого JSON
--------------------------------------------------------------------------------
Из подписываемого JSON необходимо исключить следующие параметры:
  - LogoFileName;
  - объект Signer.

Данные подписанта необходимо передавать в объект Head вместо объекта Signer
в следующем формате:

  "Head": {
    "Pinfl": "string",
    "FullName": "string",
    "Position": "string"
  }

Где:
  - Pinfl    - ПИНФЛ подписанта;
  - FullName - ФИО подписанта;
  - Position - должность подписанта.

Обеспечить корректное заполнение объекта Head данными подписанта при
формировании подписываемого JSON.


2. Добавить выбор филиалов организаций в UI
--------------------------------------------------------------------------------
В форме создания документа «Письмо НК» необходимо добавить возможность выбора
филиала для организации отправителя и организации получателя.

Для каждой стороны документа необходимо:
  - предоставить возможность выбора филиала организации;
  - сохранять выбранный филиал в данных документа;
  - передавать информацию о филиале в подписываемом JSON в соответствующих
    параметрах:
        BranchCode - код филиала;
        BranchName - наименование филиала.

Если филиал не выбран, необходимо корректно обрабатывать отсутствие его данных
в соответствии с требованиями роуминга.


3. Добавить проверку формата номера телефона
--------------------------------------------------------------------------------
При вводе номера телефона необходимо отображать пользователю подсказку
с допустимыми форматами номера, поддерживаемыми роумингом.

Необходимо:
  - изучить форматы номеров телефонов, указанные в документации роуминга;
  - отображать подсказку с допустимыми форматами при вводе номера;
  - проверять соответствие введённого номера поддерживаемому формату;
  - выводить понятное сообщение, если номер не соответствует требованиям.

Проверка должна соответствовать документации роуминга, без введения
дополнительных ограничений, не предусмотренных спецификацией.


4. Проверить совместимость формирования документа - формат соответсвует
--------------------------------------------------------------------------------
  - Проверить формирование JSON для новых документов.
  - Убедиться, что исключённые параметры LogoFileName и Signer больше не передаются.
  - Проверить корректность заполнения Head, BranchCode и BranchName.
  - Убедиться, что выбранные филиалы сохраняются при редактировании документа.
  - Проверить подписание и отправку документа в роуминг.


ОЖИДАЕМЫЙ РЕЗУЛЬТАТ
--------------------------------------------------------------------------------
  - Документ «Письмо НК» формируется в соответствии с актуальной структурой
    JSON роуминга.
  - Данные подписанта передаются через объект Head, а не через Signer.
  - Параметр LogoFileName исключён из подписываемого JSON.
  - Пользователь может выбрать филиалы отправителя и получателя, а информация
    о выбранных филиалах передаётся в BranchCode и BranchName.
  - При вводе номера телефона пользователь видит допустимые форматы и получает
    предупреждение при несоответствии требованиям роуминга.
