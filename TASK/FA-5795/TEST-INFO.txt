FA-5795 TASK DESCRIPTION ================================================================================================================================================================================================================

В разделе Настройки → Реестры необходимо доработать блок «Ответственные лица в разрезе организации».

Необходимо добавить возможность указывать, что данные директора и главного бухгалтера организации должны автоматически получаться из роуминга при формировании подписываемого JSON.

При включённой настройке выбранные в системе сотрудники для полей «Руководитель» и «Главный бухгалтер» не должны записываться в подписываемый JSON. Вместо них при формировании документа должны использоваться данные, полученные из роуминга.

Также необходимо разрешить сохранение настроек, если поля «Руководитель» и/или «Главный бухгалтер» не заполнены, но включена настройка получения реквизитов через роуминг.

Необходимо реализовать:

	1. Настройка получения данных из роуминга

		В разделе:
			Настройки → Реестры → Ответственные лица в разрезе организации
			использовать существующий чекбокс:
				«Использовать реквизиты роуминга»
				При включении данного чекбокса система должна использовать данные директора и главного бухгалтера, полученные из роуминга, при формировании подписываемого JSON.

	2. Логика для руководителя и главного бухгалтера
		
		Если «Использовать реквизиты роуминга» = включено:
			выбранный в поле «Руководитель» сотрудник не должен использоваться при формировании подписываемого JSON;
			выбранный в поле «Главный бухгалтер» сотрудник не должен использоваться при формировании подписываемого JSON;
			данные соответствующих ответственных лиц должны быть получены из роуминга;
			локально выбранные значения должны сохраняться в настройках, но игнорироваться при формировании JSON, пока активен чекбокс.

	3. Возможность сохранить настройки без выбора сотрудников

		Необходимо изменить текущую валидацию полей «Руководитель» и «Главный бухгалтер».
		Если включён чекбокс «Использовать реквизиты роуминга», система должна разрешать сохранение настроек:
			без выбранного руководителя;
			без выбранного главного бухгалтера;
			без выбора обоих сотрудников.
	4. Поведение при выключенном чекбоксе

		Если «Использовать реквизиты роуминга» = выключено, должна сохраняться текущая логика работы:
			данные руководителя берутся из выбранного в настройках сотрудника;
			данные главного бухгалтера берутся из выбранного сотрудника;
			действуют существующие правила обязательности и валидации полей.


Если по текущей логике руководитель и главный бухгалтер являются обязательными, их выбор должен требоваться при отключённом чекбоксе.
Примечание в некоторых организациях поле главного бухгалтера из роуминга возвращается пустым в этом случае в подписываемый JSON необходимо передавать только данные директора

Проблема

Настройка «Использовать реквизиты роуминга» была только у филиалов (сделана в 2021 г., FA-3714). У головной организации её не было, поэтому в подписываемый JSON всегда попадали сотрудники, выбранные в настройках.
Без выбранных руководителя и главного бухгалтера настройки нельзя было сохранить.
Решение
В блок «Ответственные лица в разрезе организации» добавлен чекбокс «Использовать реквизиты роуминга».
Если чекбокс включён, руководитель и главный бухгалтер берутся из роуминга. Выбранные сотрудники сохраняются в настройках, но в документ не попадают, поля недоступны для изменения.
При включённом чекбоксе настройки можно сохранить без руководителя и главного бухгалтера.
Если в роуминге главный бухгалтер пустой, в документ передаётся только руководитель. Формы создания документа в этом режиме не требуют бухгалтера.
API (ImportDocumentRegister): если руководитель или бухгалтер переданы в запросе, используются переданные данные. Из роуминга заполняются только пустые поля.
Та же логика применяется к филиалам.
Если чекбокс выключен, всё работает как раньше.
