ТЕСТ-КЕЙСЫ: Роль «Управление тарифом организации»
=====================================================================
Задача: добавить роль, дающую право на перезагрузку и активацию тарифа
организации; запретить эти операции пользователям без роли.

Обозначения:
  Пользователь A  - сотрудник организации С новой ролью
  Пользователь B  - сотрудник организации БЕЗ новой роли

=====================================================================
ЧАСТЬ 1. КЕЙСЫ ПО ПУНКТАМ ЗАДАЧИ
=====================================================================

---------------------------------------------------------------------
ПУНКТ 1. Добавление новой роли
---------------------------------------------------------------------

TC-001   Роль отображается в справочнике ролей    
Предусловия: пользователь с правом управления ролями.
Шаги:
  1. Открыть раздел управления ролями / настройки пользователя.
  2. Найти в списке ролей «Управление тарифом организации».
Ожидаемый результат:
  - Роль присутствует в списке, название отображается корректно (ru / uz).
  - Роль доступна для выбора.
Результат:

TC-002   Назначение роли пользователю    
Предусловия: пользователь B без новой роли.
Шаги:
  1. Открыть карточку пользователя B.
  2. Выбрать роль «Управление тарифом организации», сохранить.
  3. Обновить страницу и открыть карточку снова.
Ожидаемый результат:
  - Роль успешно назначена и сохранена.
  - В карточке пользователя роль отображается.
Результат:

TC-003   Снятие роли у пользователя    
Предусловия: пользователь A с новой ролью.
Шаги:
  1. Открыть карточку пользователя A, убрать роль, сохранить.
  2. Войти под пользователем A (или обновить сессию).
  3. Попробовать активировать / перезагрузить тариф.
Ожидаемый результат:
  - Роль снята.
  - Операции становятся недоступны (см. пункт 3 и 5).
Результат:

TC-004   Назначение роли вместе с другими ролями    
Предусловия: у пользователя есть другая роль (например, бухгалтер).
Шаги:
  1. Добавить новую роль к существующим.
  2. Сохранить и проверить права.
Ожидаемый результат:
  - Обе роли сохранены.
  - Права прежней роли не потеряны, права на тариф появились.
Результат:

TC-005   Роль не может быть назначена без прав на управление ролями    
Предусловия: пользователь B без права управления ролями.
Шаги:
  1. Попробовать назначить себе новую роль (UI и прямой API-запрос).
Ожидаемый результат:
  - Операция отклонена, роль не назначена.
Результат:

---------------------------------------------------------------------
ПУНКТ 2. Права новой роли
---------------------------------------------------------------------

TC-006   Активация тарифа пользователем с ролью    
Предусловия: пользователь A; у организации нет активного тарифа,
тариф оплачен.
Шаги:
  1. Войти под пользователем A.
  2. Открыть раздел тарифов, нажать «Активировать».
Ожидаемый результат:
  - Тариф активирован.
  - Лимиты тарифа установлены корректно.
  - Статус тарифа «Активен», даты начала и окончания верные.
Результат:

TC-007   Перезагрузка тарифа пользователем с ролью    
Предусловия: пользователь A; у организации есть тариф,
по которому операция перезагрузки допустима.
Шаги:
  1. Войти под пользователем A.
  2. Нажать «Перезагрузить тариф».
Ожидаемый результат:
  - Операция выполнена успешно.
  - Лимиты и срок обновлены согласно бизнес-логике.
Результат:

TC-008   Операции, меняющие активный тариф и лимиты    
Предусловия: пользователь A.
Шаги:
  1. Выполнить каждую операцию, меняющую текущий тариф или его лимиты (смена тарифа, применение оплаченного тарифа и т.п.).
Ожидаемый результат:
  - Все операции доступны пользователю A и выполняются корректно.
Результат:

TC-009   Просмотр тарифа пользователем с ролью    
Предусловия: пользователь A.
Шаги:
  1. Открыть раздел тарифов.
Ожидаемый результат:
  - Информация о тарифе, лимитах и сроке отображается полностью.
Результат:

TC-010   Роль даёт права только в своей организации    
Предусловия: пользователь A принадлежит организации №1; есть организация №2.
Шаги:
  1. Попробовать активировать/перезагрузить тариф организации №2 (через UI или API с подменой ID организации).
Ожидаемый результат:
  - Операция отклонена, тариф организации №2 не изменился.
Результат:

ПУНКТ 3. Запрет операций для пользователей без роли
---------------------------------------------------------------------

TC-011   Кнопка активации для пользователя без роли    
Предусловия: пользователь B без новой роли (раньше имел доступ).
Шаги:
  1. Войти под пользователем B.
  2. Открыть раздел тарифов.
Ожидаемый результат:
  - Кнопка «Активировать» скрыта или неактивна.
  - Операция недоступна.
Результат:

TC-012   Кнопка перезагрузки для пользователя без роли    
Предусловия: пользователь B.
Шаги:
  1. Открыть раздел тарифов.
Ожидаемый результат:
  - Кнопка «Перезагрузить тариф» скрыта или неактивна.
Результат:

TC-013   Прямой вызов API активации без роли    
Предусловия: пользователь B, валидный токен.
Шаги:
  1. Отправить запрос на активацию тарифа напрямую (Postman).
Ожидаемый результат:
  - HTTP 403 (или принятый в системе код отказа).
  - Тариф не изменился, лимиты не сброшены.
Результат:

TC-014   Прямой вызов API перезагрузки без роли    
Предусловия: пользователь B, валидный токен.
Шаги:
  1. Отправить запрос на перезагрузку тарифа напрямую.
Ожидаемый результат:
  - HTTP 403, данные тарифа не изменились.
Результат:

TC-015   Переход по прямой ссылке на страницу действия    
Предусловия: пользователь B.
Шаги:
  1. Открыть URL страницы активации/перезагрузки вручную.
Ожидаемый результат:
  - Доступ закрыт, показано сообщение об отсутствии прав или редирект.
Результат:

TC-016   Владелец/администратор организации без новой роли    
Предусловия: пользователь с ролью администратора организации, но
без новой роли.
Шаги:
  1. Попробовать активировать и перезагрузить тариф.
Ожидаемый результат:
  - Поведение соответствует требованию задачи: без новой роли операции недоступны (уточнить у аналитика, если отличается).
Результат:

ПУНКТ 4. Проверка всех точек входа
---------------------------------------------------------------------

TC-017   Личный кабинет организации - раздел «Тарифы»    
Шаги:
  1. Под пользователем B и пользователем A проверить все кнопки и действия раздела.
Ожидаемый результат:
  - Для B все действия по активации/перезагрузке недоступны,
    для A доступны.
Результат:

TC-018   Админ-панель - управление тарифом организации    
Шаги:
  1. Проверить доступность операций в админ-панели для разных ролей.
Ожидаемый результат:
  - Права проверяются и в админ-панели; поведение соответствует требованиям (уточнить, нужна ли роль для сотрудников админки).
Результат:

TC-019   Активация тарифа из карточки организации    
Шаги:
  1. Найти все альтернативные места активации (карточка организации, списки, контекстные меню).
  2. Проверить под пользователями A и B.
Ожидаемый результат:
  - Во всех местах действует единая проверка прав.
Результат:

TC-020   Применение оплаченного тарифа после оплаты    
Предусловия: оплата выполнена вручную пользователем.
Шаги:
  1. Под пользователем B попробовать применить оплаченный тариф.
  2. Под пользователем A выполнить то же.
Ожидаемый результат:
  - Для B отказ, для A успешное применение.
Результат:

TC-021   Все API-эндпоинты, меняющие тариф    
Шаги:
  1. Составить список эндпоинтов (активация, перезагрузка, применение, смена тарифа).
  2. Вызвать каждый с токеном B и токеном A.
Ожидаемый результат:
  - Каждый эндпоинт возвращает отказ для B и успех для A.
Результат:

TC-022   Мобильное приложение / внешняя интеграция (если есть)    
Шаги:
  1. Проверить активацию/перезагрузку через мобильное приложение или внешний API.
Ожидаемый результат:
  - Проверка роли действует и там.
Результат:

TC-023   Массовые операции (если есть)    
Шаги:
  1. Попробовать выполнить массовую активацию/перезагрузку без роли.
Ожидаемый результат:
  - Операция отклонена, ни один тариф не изменён.
Результат:

ПУНКТ 5. Сообщение об отсутствии прав
---------------------------------------------------------------------

Предусловия: пользователь B.
Шаги:
  1. Попытаться выполнить операцию (если элемент виден).
Ожидаемый результат:
  - Показано понятное сообщение, например: «У вас нет прав на управление тарифом организации. Обратитесь к администратору».
  - Без технических ошибок и стектрейсов.
Результат:

TC-025   Сообщение в API-ответе    
Шаги:
  1. Вызвать эндпоинт активации с токеном B.
Ожидаемый результат:
  - Ответ содержит код ошибки и понятный текст.
  - Формат ответа единый с остальными ошибками системы.
Результат:

TC-026   Локализация сообщения (ru / uz)    
Шаги:
  1. Переключить язык интерфейса на ru, затем на uz.

Ожидаемый результат:

Результат:

TC-027   Сообщение не дублируется и не пропадает    
Шаги:
  1. Несколько раз подряд попытаться выполнить операцию без роли.
Ожидаемый результат:
  - Каждый раз показывается одно сообщение, интерфейс не зависает.

=====================================================================
ЧАСТЬ 2. ДОПОЛНИТЕЛЬНЫЕ КЕЙСЫ ПО ЗАДАЧЕ
=====================================================================

TC-028   Повторная активация до окончания срока не обнуляет лимиты    
Предусловия: у организации активен оплаченный тариф, часть лимита
уже израсходована; пользователь A.
Шаги:
  1. Запомнить остаток лимитов.
  2. Под пользователем A нажать «Активировать» повторно.
  3. Сравнить лимиты до и после.
Ожидаемый результат:
  - Лимиты не сбрасываются (или повторная активация блокируется сообщением). Это первопричина проблемы - роль не должна быть единственной защитой.
Результат:

TC-029   Повторная активация без роли не сбрасывает лимиты    
Предусловия: активный тариф, часть лимита израсходована;
пользователь B.
Шаги:
  1. Попытаться активировать тариф повторно (UI и API).
  2. Проверить лимиты.
Ожидаемый результат:
  - Отказ, остаток лимитов не изменился.
Результат:

TC-030   Автоактивация тарифа после оплаты (callback)    
Предусловия: организация оплачивает тариф через платёжную систему.
Шаги:
  1. Выполнить оплату.
  2. Дождаться callback от платёжной системы.
Ожидаемый результат:
  - Тариф активируется автоматически независимо от ролей пользователей (процесс системный).
  - Ошибки прав не возникает.
Результат:

TC-031   Автоматические процессы (cron/джобы) по тарифам    
Шаги:
  1. Дождаться/запустить фоновое продление или деактивацию тарифов.
Ожидаемый результат:
  - Фоновые процессы работают как раньше, проверка роли их не блокирует.
Результат:

TC-032   Миграция: существующие пользователи после релиза    
Предусловия: стенд после применения миграции.
Шаги:
  1. Проверить, у кого из пользователей появилась новая роль (например, у владельцев организаций).
  2. Проверить остальных пользователей.
Ожидаемый результат:
  - Роль выдана только согласованным пользователям.
  - У организаций не пропала возможность активировать тариф.
Результат:

TC-033   Организация без пользователя с новой ролью    
Предусловия: в организации никто не имеет новой роли.
Шаги:
  1. Попытаться активировать тариф.
Ожидаемый результат:
  - Понятное сообщение; есть путь решения (обращение к админу организации / в поддержку).
Результат:

TC-034   Изменение роли при активной сессии    
Предусловия: пользователь A залогинен.
Шаги:
  1. Администратор снимает роль у пользователя A.
  2. Пользователь A, не перелогиниваясь, пытается активировать тариф.
Ожидаемый результат:
  - Права проверяются актуально: операция отклонена (или после обновления токена - по принятой в системе логике).
Результат:

TC-035   Одновременная активация двумя пользователями    
Предусловия: два пользователя с новой ролью в одной организации.
Шаги:
  1. Одновременно нажать «Активировать» с двух сессий.
Ожидаемый результат:
  - Тариф активируется один раз, лимиты не обнуляются дважды, второй запрос получает отказ или идемпотентный ответ.
Результат:

TC-036   Двойной клик по кнопке активации    
Шаги:
  1. Быстро дважды нажать «Активировать».
Ожидаемый результат:
  - Выполняется одна операция, лимиты не сбрасываются повторно.
Результат:

TC-037   Аудит/логирование действий с тарифом    
Шаги:
  1. Выполнить активацию/перезагрузку пользователем A.
  2. Попытаться выполнить без роли пользователем B.
  3. Проверить логи/историю.
Ожидаемый результат:
  - Успешные операции логируются (кто, когда, что изменено).
  - Попытки без прав фиксируются (если предусмотрено).
Результат:

TC-038   Подмена ID организации/пользователя в запросе    
Шаги:
  1. Пользователем B отправить запрос с подменённым ID пользователя или организации, у которых есть роль.
Ожидаемый результат:
  - Права определяются по токену, а не по данным из тела запроса.
  - Операция отклонена.
Результат:

TC-039   Регрессия: остальные функции пользователя B    
Предусловия: пользователь B без новой роли.
Шаги:
  1. Проверить остальные функции, доступные его ролям (счета -фактуры, отчёты, справочники). 
Ожидаемый результат:
  - Остальные функции работают как раньше, ограничение затронуло только операции с тарифом.
Результат:

TC-040   Регрессия: просмотр тарифа и лимитов без роли    
Предусловия: пользователь B.
Шаги:
  1. Открыть раздел тарифов и просмотреть информацию.
Ожидаемый результат:
  - Просмотр тарифа, остатка лимитов и срока доступен (если не оговорено иное).
Результат:
