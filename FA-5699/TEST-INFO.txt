========================================================================================
ЦЕЛЬ
========================================================================================
Обеспечить возможность автоматического получения и выбора автотранспорта в ТТН после перехода на новый метод регулятора /Api/Waybill/Transports/v2, сохранив существующую функциональность кэширования и отображения транспортных средств по ИНН/ПИНФЛ владельца.


-----------------------------------------------------------------------------------------
ПРЕДПОСЫЛКИ
-----------------------------------------------------------------------------------------
В предыдущей реализации использовался метод:
-----------------------------------------------------------------------------------------
    GET /Api/Waybill/Transports?companyInn={INN}

    Метод возвращал список транспортных средств для конкретного ИНН/ПИНФЛ, что позволяло:
    - получать список автомобилей владельца;
    - отображать автомобили в выпадающем списке ТТН;
    - сохранять автомобили в локальной БД с привязкой к владельцу;
    - использовать кэшированные данные при недоступности сервисов ГАИ или роуминга.

    После перехода на новый метод:

    POST /Api/Waybill/Transports/v2?lang=ru

    в запрос передается массив ИНН/ПИНФЛ:

    {
    "TinOrPinfls": ["123456789", "987654321"],
    "RegNumbers": [],
    "Date": "2026-07-16"
    }

    Ответ содержит общий список автомобилей без указания владельца:

    {
    "success": true,
    "data": [
        {
        "regNo": "01A123BC",
        "model": "Cobalt",
        "ownershipType": 1,
        "transportType": 1
        }
    ]
    }

    В результате невозможно определить, какой автомобиль относится к какому ИНН/ПИНФЛ, что делает невозможным корректное сохранение данных в локальную базу.


-----------------------------------------------------------------------------------------
РЕШЕНИЕ
-----------------------------------------------------------------------------------------

    До получения доработок со стороны регулятора изменить механизм получения транспорта.

    Вместо передачи массива владельцев выполнять отдельный запрос для каждого ИНН/ПИНФЛ.

    Пример

    Для владельцев:
    - 123456789
    - 987654321

    выполнять два отдельных запроса:

    {
    "TinOrPinfls": ["123456789"],
    "RegNumbers": [],
    "Date": "2026-07-16"
    }

    и

    {
    "TinOrPinfls": ["987654321"],
    "RegNumbers": [],
    "Date": "2026-07-16"
    }

    Все автомобили, полученные в ответе на запрос, должны быть сохранены с привязкой к ИНН/ПИНФЛ, отправленному в данном запросе.


-----------------------------------------------------------------------------------------
ТРЕБУЕМЫЕ ИЗМЕНЕНИЯ
-----------------------------------------------------------------------------------------

---------------------------------------------------------------------------------------------
    BACKEND
---------------------------------------------------------------------------------------------

    1. Получение транспорта
        При запросе списка транспортных средств:
        1) Определить ИНН/ПИНФЛ владельца.
        2) Выполнить вызов /Api/Waybill/Transports/v2.
        3) Передавать в массиве TinOrPinfls только одного владельца.
        4) Получить список транспортных средств.
        5) Сохранить полученные данные в локальную БД.

    2. Кэширование
        Для каждого автомобиля сохранять:
        - ИНН/ПИНФЛ владельца;
        - госномер;
        - модель;
        - тип собственности;
        - тип транспорта;
        - дату обновления.

        Пример структуры хранения:

        Поле             | Описание
        -----------------|---------------------------
        owner_inn_pinfl | ИНН/ПИНФЛ владельца
        reg_no           | Государственный номер
        model            | Модель
        ownership_type   | Тип собственности
        transport_type   | Тип транспорта
        updated_at       | Дата обновления

    3. Использование кэша
        Если сервис роуминга или ГАИ недоступен:
        - использовать последний сохраненный список автомобилей;
        - отображать пользователю данные из локальной БД.

---------------------------------------------------------------------------------------------
    FRONTEND
---------------------------------------------------------------------------------------------
    Логика работы интерфейса остается прежней:
        1) Пользователь вводит ИНН/ПИНФЛ.
        2) Система получает список автомобилей.
        3) Автомобили отображаются в выпадающем списке.
        4) Пользователь выбирает необходимый транспорт.

    Изменения интерфейса не требуются.


---------------------------------------------------------------------------------------------
    ТРЕБОВАНИЯ К ПРОИЗВОДИТЕЛЬНОСТИ
---------------------------------------------------------------------------------------------
    - Не выполнять повторный запрос к регулятору при наличии актуальных данных в кэше.
    - Использовать данные из локальной БД при открытии формы ТТН.
    - Обновлять данные только при отсутствии записи либо при истечении срока актуальности кэша.


    КРИТЕРИЙ ПРИЕМКИ

    - Данные успешно получены.
